## How it was done

1. **Varuuna's reviewed merges first**, cherry-picked with `-x` (`-m 1` for the merge commits). They are the
   `ComboShip` `main` merges of soh 9.3.1 (`03a3d51dc`, pin and log `b3a0a4433`) and libultraship `da6daf1a5`
   (`189908d85`, pin and log `a771b3d29`, Context.cpp fix `16525a077`). Their logs are
   [2026-10-19-soh.md](2026-10-19-soh.md) and [2026-10-19-libultraship.md](2026-10-19-libultraship.md).
2. A vendor commit for each of those targets (tree identical to upstream, checked against the upstream
   trees) was grafted into our history as an ancestor, as described in `docs/UPSTREAM_MERGES.md`.
3. The newer tails were merged the normal way from `vendor-<name>` branches built at the current tips:
   libultraship `da6daf1a5` → `57e6d409a`, soh `f0599f96f` → `64df9cb8e`, 2Ship `e8757c14a` → `7e3d051be`.
   `scripts/upstream-merge.ps1` was not run: its `--depth` blob hydration would make the shared repo
   shallow, so the vendor commits were built by hand from depth-1 fetches (same plumbing).

## Things this pass changes for players and for the next pass

- **Enum renumbering.** `RandomizerCheck` (`RC_FISHERMANS_HAT` and the Fire Temple Goron checks), `RandomizerInf`,
  `RandomizerSettingKey` (`RSK_NAYRUS_LOVE_USES`) and 2Ship's `RandoOption` and `RandoEvent` (`RO_ADDITIONAL_ITEMS`,
  `RE_MEET_KOTAKE_WOODS`, `RE_STONE_TOWER_TEMPLE_DEEP_POOL_UNDERWATER_SWITCH`) all gained entries mid-enum. Rando saves
  made on the previous build index these arrays and flag sets, so they must be retired: bump `COMBO_RELEASE_VERSION`
  major.minor (the container path disables SoH's own stale-save guard).
- **New seed features** that the fill-parity checklist ([COMBO_FILL_PARITY.md](../COMBO_FILL_PARITY.md)) should be walked
  against: SoH Fisherman's Hat and Fire Temple Goron shuffles, consumable Nayru's Love, faster generation (`fill.cpp`),
  2Ship's Additional Items (`GeneratePools.cpp`, `OnFileCreate.cpp`, the spoiler).
- **Config.** SoH adds `ConfigVersion8Updater` (Sleeping to Sleepless Waterfall CVar rename). 2Ship adds a
  `ConfigVersion2Updater` (Great Fairy Sword on B to Active Item on B). In the combo the shared `Config` registers
  SoH's updaters first, so 2Ship's v1 and v2 collide with SoH's and are not registered (`Config::RegisterVersionUpdater`
  keeps the first one per version).
